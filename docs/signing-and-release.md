# Release & signing process (Phase 0, A7)

Status: **dry-run only — artifacts are currently unsigned.** Signing/notarization
is documented here before it exists so the process is a checklist, not a project.

## Release dry-run (active now)

- Config: `dist-workspace.toml` (cargo-dist 0.32), `[profile.dist]` in `Cargo.toml`.
- CI: `.github/workflows/release.yml` (generated by `dist generate`; do not edit by
  hand — change config and re-run `dist generate`).
- Trigger: push a tag `v*` (e.g. `v0.1.0`). Every tag builds on all target platforms
  and uploads archives + SHA-256 checksums as a draft GitHub release.
- Local equivalent: `dist plan` (prints exactly what a tag would produce).
- Targets: `aarch64/x86_64-apple-darwin`, `aarch64/x86_64-unknown-linux-gnu`,
  `x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`.

## Signing — when adopted (post-Phase 0 checklist)

| Platform | Process | Secrets |
| --- | --- | --- |
| macOS | Developer ID Application certificate → `codesign` → notarization via `notarytool` → staple | Apple API key + issuer ID stored as GitHub secrets / OIDC |
| Windows | Authenticode signtool with an OV/EV code-signing certificate | Cert in hardware token or Azure Trusted Signing |
| Linux | no code signing; tarballs ship SHA-256 checksums (already generated) | — |

Rules when signing lands:

- Sign **runtime packs and models** with a SHA-256 manifest too (A7) — `oca doctor`
  verifies them. Unsigned packs are side-loadable but reported by `doctor`.
- Signing is proven early, not at Phase 18: this dry-run CI stays green while
  signing is added incrementally.
- Never put credentials in the repo; release artifacts must build on a fresh,
  no-network machine (Phase 18 exit criterion).

## Bumping the repository URL

The URL in `[workspace.package] repository` is currently a placeholder. To set the
real one:

```sh
# edit `repository =` in Cargo.toml, then:
dist generate   # regenerates .github/workflows/release.yml
```
