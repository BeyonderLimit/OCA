# ADR-0030: RAG — embedding seam, vector index in the cache DB, hybrid search

- Status: Accepted · Date: 2026-10-20 · Code: **D8, A6, A8** · AGENTS rules 2, 3, 6, 8
- Source: `OCA-architechture.md` Part II §23 (D8 closed by the Phase 5 spike) · plan: `OCA-implementation.md` §3 Phase 11 · spec: `OCA-build.md` §7.5 (imported sources as context)

## Decision

- **New crate `oca-rag`** (crate→phase table) holds everything retrieval: chunking, reference import, EPUB extraction, incremental embedding sync, and hybrid search. It depends on `oca-ai` (allowed — the smoke gate keeps the *engines* AI-free, and no engine depends on `oca-rag`). `oca-ai` gains two seams it owns (rule 6 — one touchpoint per runtime family): `trait LanguageModel` for generation and **`trait Embedder`** for embeddings; both llama.cpp runtimes are spawned subprocesses of the same `llama-server` binary, one model per process, A6 slots (`HeavyModel::Embeddings`).
- **Vectors live in the same `.oca/cache/oca.db`** (D8) — `sqlite-vec` registers through `sqlite3_auto_extension` in `Db::open`, so every connection can `CREATE VIRTUAL TABLE … USING vec0`. The physical `rag_vectors` table is created by `oca-rag` at the observed dimension (a mock knows it up front via `Embedder::dim()`; a real runtime reveals it on first embed); a dimension change drops and rebuilds — vectors are derived data, never canonical (rule 2), and `oca reindex` regenerates them. `rag_chunks` (migration 2, `UNIQUE(rel, idx)`) stores chunk text + content checksum + embed-model name, which is what makes the sync incremental: a chunk re-embeds only when its checksum, the model name, or the index dimension changed.
- **Hybrid = FTS5 ∥ kNN, fused late** (`oca-rag::hybrid_search`): lexical rank and vector rank (cosine from `vec0` kNN) each vote `1/(1+rank)`, weighted 0.5/0.5, deduped by rel, deterministically ordered (score desc, rel asc — no ties, no randomness). The vector half is silently skipped when the indexed model name ≠ the loaded model (a different model's vectors are meaningless, keywords still answer). **No embedder at all = keyword-only search that works exactly as before** (rule 3) — search never requires a model, an import never fails without one.
- **The Retriever seam** (Phase 8 context engine): `HybridSearch` (trait in `oca-ai`) + `RetrievedDoc`; `Ai::set_search` wires a live `Rag` in the frontends; `prepare_continue_scene` takes `Option<&dyn HybridSearch>` so imported material can reach a prompt — everything from `library/` arrives **untrusted** (`<untrusted-source>`, A8), because references are imported, not authored.
- **`oca import <file>...`** copies Markdown / text / EPUB into `library/<slug>.md` with provenance frontmatter (`id`, `title`, `source_type`, `source_path`, `imported`), title preferring the document's own H1, slugified for collision-free `-N` names. Import auto-snapshots first (the Phase 6 hook), refuses read-only, then reindexes + syncs embeddings. EPUB extraction is a minimal zip+XML reader (spine order, OPF title, HTML stripped to prose) — an importer, not a reader.
- **Embeddings-only mode is first-class**: `bootstrap_embeddings` needs neither an LLM nor a runtime pack — only a model file under `~/.oca/models/embeddings` (or `[ai] embeddings_dir`/`mock = true`). The offline mock (`MockEmbedder`, deterministic FNV bag-of-tokens) skips the residency governor (there is no RAM to arbitrate) so demos compose the AI panel with hybrid search freely; the real embedder claims the Embeddings slot and a load failure — e.g. the LLM already resident (A6) — degrades to keyword results with one honest note, never an error.
- **Frontends stay thin (rule 8)**: the CLI's `search` prints fused hits with `[reference]` markers and a `· hybrid` suffix; `reindex` prints the embed-sync line; the TUI's Ctrl-F panel maps `RagHit`s into the existing hit rows and loads the runtime lazily on the first query. All chunking/fusion/sync logic lives in `oca-rag`; the TUI search panel contains none.

## Consequences

- The A10 search budgets still describe the lexical half; the vector half adds one kNN query plus one small-batch embed per search — bounded by the 32-text embed batches in sync, not per-hit.
- Deleting every model file leaves search, import, and reindex fully working (keyword-only, honest notes) — rule 3 holds end-to-end; the vector table simply stays empty.
- A dimension or model change invalidates vectors wholesale (re-embed on next sync); per-chunk staleness is by content checksum, so day-to-day edits re-embed only what changed.
- Real-model verification (a BGE-class embedding model through a spawned `llama-server`) stays manual on this machine, like every other runtime path — the subprocess seam is covered by the self-invoking fake server.
